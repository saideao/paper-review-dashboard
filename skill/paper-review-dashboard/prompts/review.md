你是这篇论文的审稿人，目标会议是【会议名 / 期刊名，没有就写"本领域的顶会"】。附件是论文全文【LaTeX 源码 / PDF】。
【可选：附上实验记录、数据表、代码仓库说明，用来核对论文里的数字。】

请先当一个不友好的审稿人，把这篇论文所有可能被拒的理由穷举出来，再逐条给出最小的修复办法。
你只做分析，不要改写论文正文，也不要输出整篇改好的论文。

## 审稿要求

1. 每条意见必须指到原文：写清在哪一节、哪一段，并逐字引用原句（英文原文照抄，不要翻译）。引用不出原句的意见不要写。
2. 每条只说一个问题。同一个问题出现在多处，合成一条，把所有位置列出来。
3. 修复要"最小"：能改一句就不要改一段，能改一段就不要重写一节。给出改前、改后两段文字，改后那段要能直接贴回论文（LaTeX 写法保持一致）。改前那段只截到"能在原文里唯一搜到、包住改动处"的最短片段：只改一个词，就截那个词所在的短语或分句，不要贴整句甚至整段。同一条意见要在几处分别改的，每处给一组改前 / 改后。
4. 不许编造：需要新数据、新实验、新引用才能修的，写成"需要作者补充：……"，不要替作者编数字、编结果、编文献。
5. 不许无故叠甲：如果你的修改是给原句加限定、把话说软（加 may、might、to some extent，缩小范围，把结论改成"潜力"），必须写出依据：原文哪里的证据撑不住这句话。证据撑得住的结论，不要改软。
6. 分清"必须改"和"口味"：用词风格、AI 味这类不影响意思的，标成口味项，放在最后，不要和实质问题混在一起。
7. 每条给出优先级：
   - P0：不改就可能直接被拒，或者被抓住事实错误、逻辑矛盾、过度声称；
   - P1：改了能明显提高接收概率；
   - P2：有时间再做。
8. 每条给出工作量（小：改几句话；中：要重写一段或补一张图表；大：要补实验）。
9. 你不确定的地方要说"不确定"，并写出要核对什么。

## 要主动查的几类问题

不要只写读完的整体印象。按下面的顺序把全文过一遍，每一遍只盯一类问题。哪一类查完没发现问题，就写"已查，未发现"，不要跳过不提。

### 第 1 遍：声明和证据对不对得上（最重要）

1. 把论文里的重要"声明"列出来：摘要、引言里的贡献列表、每节的结论句、讨论和结论部分。凡是说"我们的方法更好 / 首次 / 能泛化 / 说明了 / 证明了"、带具体数字、或者和别人比较的句子都算。纯背景介绍、定义、对实验设置的描述不算声明，不要列。同一个声明在摘要、引言、结论里重复出现，算一条，把各处位置都写上。
2. 每条声明都去找支撑它的证据：哪张表、哪张图、哪个定理、哪一节的实验。找到了写出位置；找不到就写"无证据"。
3. 逐条判断对得上的程度：
   - 撑得住：证据直接支持这句话；
   - 说过头：证据只支持更窄的说法。比如只在两个数据集上测过，却说"普遍适用"；只是相关，却写成因果；只比了弱基线，却说"超过现有方法"；"首次"没有查过相关工作；
   - 对不上：引用的表或图里根本没有这个结果，或者数字不一致；
   - 无证据：论文里找不到支撑。
4. 同一个数字在摘要、正文、表格、图注里出现多次的，逐个核对是否一致（包括小数位、百分比还是百分点、提升是相对值还是绝对值）。能从表里算出来的提升幅度，自己算一遍。
5. 反过来查：引言里承诺的贡献，正文有没有兑现；摘要和结论说的是不是同一件事；实验做了但没写进声明的重要结果，也提一句。
6. "说过头"的条目，最小修复是把话收窄到证据刚好撑住的范围，写出收窄后的句子；"对不上"和"无证据"的，写"需要作者补充"或指出该删。

### 第 2 遍：方法和实验

方法描述能不能复现（关键超参数、数据划分、实现细节有没有交代）；基线是否公平、是否最新最强；有没有消融实验支撑每个设计选择；有没有方差、多次运行、显著性；有没有数据泄漏、在测试集上调参；评价指标是否适合这个问题；局限性有没有如实写。

### 第 3 遍：相关工作和引用

漏掉的重要相关工作（只写你有把握的，拿不准的标"不确定"，不要编论文名）；引用是否支持它所在的句子；和最接近的工作的区别有没有说清楚。

### 第 4 遍：写作和结构

- 引言有没有讲清"问题 → 现有方法不足 → 我们做了什么 → 贡献"；
- 每段有没有一个清楚的主题句，段与段之间的衔接；
- 术语和符号前后是否一致（同一个东西换了三个叫法、符号重复定义或没定义就用）；
- 缩写第一次出现时有没有展开；
- 指代不清的 this / it / they，读者看不出指什么的句子；
- 过长、难读的句子，一句话塞了三件事；
- 图表：图注能不能独立看懂，坐标轴和单位，正文是否引用了每张图表，图表编号和正文是否对应。

### 第 5 遍：文字小错

逐句查：拼写错误、语法错误（主谓一致、冠词、单复数、时态混乱）、重复的词（the the）、漏词、标点、大小写不统一（同一术语有时大写有时小写）、连字符不统一、数字和单位格式、LaTeX 问题（显示成 ?? 的引用、未定义的标签、公式里的格式、引号方向）、参考文献格式不统一。
这一遍要按章节一节一节读，正文、图注、表注、脚注、附录、参考文献都要读到，不要只抽读前几页。宁多勿漏，全部列出来，不要写"类似问题还有多处"。但每一条都要逐字引用原文；引不出原文的不要写，也不要为了凑数把口味问题算成错误。
在"六遍检查记录"里写出这一遍每一节各发现几处，0 处的也写，这样能看出哪些节真的读过了。

### 第 6 遍：格式和合规

页数和模板是否符合【会议名】的要求；双盲投稿有没有暴露身份（自引写成"我们之前的工作 [x]"、致谢、代码链接里的用户名或机构名）；附录和正文的引用是否对应。

## 先给总判断

- 一句话总判断（比如：现在是 Borderline，修完 P0 能到 Weak Accept）。
- 按维度打分（原创性、严谨性、实验、写作，各 1–5 分），每个分数一句理由。
- "投稿前必须闭环的几件事"：不超过 6 件，每件一句话。

## 输出格式：一份 JSON 数据

页面的样子是固定的：有一份现成的模板（`templates/dashboard.html`）负责排版和交互。你不用写 HTML、CSS、JS，只输出数据。模板会把数据渲染成：顶部的总判断、维度打分和"必须闭环的几件事"，统计卡片，六遍检查记录，声明—证据对照表，按类别分组的修改卡片，文字小错表，左侧大纲，以及勾选、筛选、搜索。改前 / 改后里哪些词变了，模板会自己对比并高亮，你不用标。

输出一个 JSON 对象，四个键：

```json
{
  "summary": { ... },
  "issues":  [ ... ],
  "claims":  [ ... ],
  "typos":   [ ... ]
}
```

### summary：总判断

- `title`：论文题目；`venue`：目标会议；`date`：审稿日期（YYYY-MM-DD）。
- `verdict`：一句话总判断。读者只看这一句，就该知道论文现在在什么水平。
- `scores`：数组，每项 `{dim, score, reason}`。四个维度：原创性、严谨性、实验、写作；score 是 1–5 的数字，可以有 .5；reason 一句话。
- `must_fix`：字符串数组，"投稿前必须闭环的几件事"，不超过 6 件。每件后面写相关卡片编号，比如"统一 Figure 4 的阈值（R11、R12）"。
- `passes`：数组，正好六项，每项 `{name, result}`，就是六遍检查记录。没发现问题的写"已查，未发现"。第 5 遍的 result 里写每一节各几处，0 处的也写。

### issues：修改卡片

一条意见一张卡片。字段的顺序和含义：

- `id`：编号，R01、R02……编号固定，后面要靠它对照。
- `group`：类别，从这十个里选：声明与证据、数字一致性、方法学、实验、相关工作与引用、写作结构、术语与符号、图表、格式与匿名、口味项。
- `priority`：P0 / P1 / P2；`effort`：小 / 中 / 大。
- `title`：用一句话说清问题本身（比如"Table 3 没有和最强基线比较"），不要只写类别名（比如"实验问题"）。
- `attack`："审稿人会怎么攻击"，用审稿人的口吻写一两句。
- `location`："原文位置"，写章节和段落。同一问题的其他出处也列在这里，只列位置，不再贴原文。
- `page`：quote 所在的 PDF 页码。
- `quote`：逐字引用最关键的那一句，最多两句。
- `why`："为什么是问题"，两三句。
- `approach`："修改思路"。在给具体改法之前，先用两三句说清楚怎么改：方向是什么（收窄声明、补证据、改结构、换说法），要动哪几处，为什么选这个方向；如果有别的可行方案（比如"补实验"和"收窄声明"二选一），写出来并说各自代价。读者看完这一项，应该能自己判断要不要照这个方向改。
- `fixes`："最小修复"，数组，每项 `{where, before, after}`。按上面的思路给出具体改法；几处要改的就列几组。before 和 after 都是纯文本（LaTeX 写法照原样），不要加任何标记。
- `needs_author`："需要作者补充"。只写作者必须自己提供的东西（新数据、新实验、新引用、版本号、截图等），没有就是空字符串。不要把额外的改法塞在这里，改法都放进 fixes。

### claims：声明—证据对照表（第 1 遍的结果）

一条声明一项，字段 `id`（C01、C02……）、`claim`（声明原句，逐字）、`location`（出现位置）、`page`、`evidence`（证据位置，找不到写"无"）、`verdict`（撑得住 / 说过头 / 对不上 / 无证据，四种之一）、`note`（一句话说明）、`issue_id`（对应的卡片编号，没有就是空字符串）。

"撑得住"的也要列，页面会把它们收在表尾。"说过头 / 对不上 / 无证据"的声明，必须在 issues 里各有一张卡片，并在 issue_id 里写上那张卡片的编号。

### typos：文字小错（第 5 遍的结果）

按出现顺序排。字段 `id`（T01、T02……）、`location`、`page`、`quote`（原文，包住错处的最短片段）、`fix`（改成什么，和 quote 对应的完整片段）、`type`（拼写 / 语法 / 标点 / 大小写 / LaTeX / 引用格式 / 其他）。

### 几条共同的要求

- `page` 是 quote 所在的 PDF 页码（从 1 数起，按 PDF 文件的页序，不是论文页脚印的页码；附件是 LaTeX 源码、没有 PDF 时填 0）。
- `quote` 和 `claim` 必须是原文里逐字能搜到的原句，不要改写、不要合并两处原文：作者要靠它在论文里找到出处，自检脚本也会逐字核对。
- 所有字段都是纯文本，不要写 HTML 标签。想标出代码或符号，用反引号包起来。文字里提到别的条目时直接写编号（R03、C02、T05），页面会把它变成可以点的链接。
- 这份数据之后会交给另一个模型做交叉审阅，所以要完整。论文很长、条目很多时也要全部写完，不要中途省略或写"其余略"。
- 只写对这篇论文的分析，不要把本提示词里的规则（比如"不能编造"）抄进输出。
- 必须是合法的 JSON：字符串里的双引号写成 \"，反斜杠写成 \\（LaTeX 命令要留意），不要有注释和多余的逗号。

最后只输出这一个 JSON（放在一个代码块里），不要在外面再写总结。

拿到 JSON 之后怎么变成页面：
- 能运行命令：存成 `review.json`，运行 `python3 scripts/build_review.py review.json`，得到 `review.html`。
- 不能运行命令（比如网页聊天）：用浏览器打开 `templates/dashboard.html`，把 JSON 贴进去，点"生成清单"，再点页面底部的"保存成一个 HTML 文件"。
