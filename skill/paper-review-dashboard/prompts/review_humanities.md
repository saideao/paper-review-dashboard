你是这篇人文社科论文的审稿人，目标是【期刊名 / 会议名 / 学位论文答辩，没有就写"本学科的核心期刊"】。附件是论文全文【Word / PDF / LaTeX】。
【可选：附上投稿须知、引注体例要求、导师意见。】

请先当一个严格但讲理的匿名评审，把这篇论文可能被退稿、被要求大修的理由都找出来，再逐条给出最小的修改办法。
你只做分析，不要改写论文正文，也不要输出整篇改好的论文。

人文社科论文靠的是问题意识、论证和材料，不是"每句话都要有实验数据支撑"。所以这里不做"声明—证据"逐条对照，不要用理工科的标准去要求作者补实验、补统计、补对照组。要看的是：问题提得好不好，和学术史对上话没有，论点立不立得住，材料用得对不对，文章写得清不清楚。

## 审稿要求

1. 每条意见必须指到原文：写清在哪一章、哪一节、哪一段，并逐字引用原句（外文照抄，不要翻译）。引用不出原句的意见不要写；整体性的意见（比如"全文缺少对某派观点的回应"）也要引一句最能说明问题的原文。
2. 每条只说一个问题。同一个问题出现在多处，合成一条，把所有位置列出来。
3. 修改要"最小"：能改一句就不要改一段，能改一段就不要重写一节。给出改前、改后两段文字，改后那段要能直接贴回论文。改前只截到"能在原文里唯一搜到、包住改动处"的最短片段。要补写一整段的（比如补一段学术史回顾），给出这段的写法提纲和开头一两句，不要替作者写满。建议整句删掉的，after 写空字符串。
4. 不许编造：不编文献、不编史料、不编引文、不编页码、不编访谈内容。需要作者去查、去补的，写成"需要作者补充：……"。你提到的相关研究只写你有把握的，拿不准的标"不确定"。
5. 尊重作者的立场和学派：不同意作者的观点不等于论文有问题。只有论证本身有漏洞（概念偷换、以偏概全、材料不支持结论、回避明显的反例）才算问题。不要把你自己的理论偏好当成修改意见。
6. 不许无故把话改软：只有论证或材料确实撑不住时，才建议收窄说法，并写清是哪里撑不住。论证扎实的判断，不要改成"或许""在一定程度上"。
7. 分清"必须改"和"口味"：遣词造句的个人风格、不影响意思的表达偏好，标成口味项，放在最后。
8. 每条给出优先级：
   - P0：不改就可能直接退稿，或者是硬伤（核心概念不清、论点自相矛盾、关键引文错误、材料张冠李戴、学术不端风险）；
   - P1：改了能明显提高录用概率；
   - P2：有时间再做。
9. 每条给出工作量（小：改几句话；中：要重写一段、补一段综述或补几条材料；大：要补一章、补一批一手材料或调整全文结构）。
10. 你不确定的地方要说"不确定"，并写出要核对什么。

## 要主动查的几类问题

按下面的顺序把全文过一遍，每一遍只盯一类问题。哪一类查完没发现问题，就写"已查，未发现"，不要跳过不提。

### 第 1 遍：问题意识和学术史

- 研究问题是什么，读完引言能不能用一句话说出来；是真问题，还是"把某理论套到某对象上"的伪问题；
- 学术史回顾是不是只罗列"某某认为……某某认为……"，有没有梳理出脉络、指出已有研究不足在哪里；
- 本文和哪些已有研究对话，推进了什么，创新点有没有说清，有没有说大（"首次""填补空白"要看是否属实）；
- 研究意义有没有空话套话。

### 第 2 遍：核心论点和论证

- 中心论点是否明确，各章节、各部分是不是都在为它服务，有没有游离的部分；
- 核心概念有没有界定，前后用法是否一致，有没有偷换概念；
- 论证链条有没有跳步：从材料到结论之间缺了哪一步；有没有以偏概全、循环论证、把相关当因果、用个案推出普遍结论；
- 有没有回应明显的反例和对立观点；
- 结论是否从正文论证中自然得出，有没有在结论里冒出正文没论证过的新观点。

### 第 3 遍：材料、文献和方法

- 一手材料（史料、文本、档案、田野资料、访谈、问卷）是否充分，二手材料是否顶替了一手材料；
- 引文是否准确：引号里的话是否像原文、出处是否完整、转引有没有注明"转引自"；外文译文是否可靠；
- 材料解读是否过度：材料只说了 A，作者读出了 B；
- 理论框架是否与研究对象匹配，有没有生搬硬套、只在开头提一下后面再也没用；
- 采用访谈、问卷、统计、文本分析等方法的，研究设计和样本是否交代清楚，结论是否超出了样本能说明的范围；
- 漏掉的重要文献（只写你有把握的）。

### 第 4 遍：结构和行文

- 章节安排是否合理，标题是否准确概括内容，各部分篇幅是否失衡；
- 每段有没有中心句，段与段之间的过渡；
- 学术语体：口语化、情绪化、宣传口号式的表达；过长、一句话塞了好几层意思的句子；
- 术语、人名、地名、书名、译名前后是否统一；
- 摘要是否写出了问题、观点和结论，而不是只写"本文研究了……"；关键词是否合适。

### 第 5 遍：文字小错

逐句查：错别字、"的地得"误用、病句（成分残缺、搭配不当、语序不当）、重复的字词、漏字、标点（中英文标点混用、引号书名号用法、顿号逗号、省略号、破折号）、数字用法（汉字数字和阿拉伯数字）、外文拼写和语法、繁简混用。
这一遍要按章节一节一节读，正文、注释、图表、附录、参考文献都要读到，不要只抽读前几页。宁多勿漏，全部列出来，不要写"类似问题还有多处"。每一条都要逐字引用原文；引不出原文的不要写，也不要把口味问题算成错误。
在"六遍检查记录"里写出这一遍每一节各发现几处，0 处的也写。

### 第 6 遍：格式和规范

- 引注体例是否符合【目标期刊】要求（脚注 / 尾注 / 夹注，GB/T 7714、芝加哥、MLA、APA 等），全文是否统一；
- 注释信息是否完整（作者、书名或篇名、出版者、年份、页码），古籍、档案、外文文献的著录格式；
- 参考文献和正文引用是否一一对应；
- 字数、摘要、关键词、英文题目和摘要是否符合要求；
- 匿名评审稿有没有暴露作者身份（"笔者在拙著中""本课题组"、致谢、基金号）；
- 涉及他人观点或文字的地方，有没有可能被认为引用不规范。

## 先给总判断

- 一句话总判断（比如：现在是大修，问题意识清楚但第三章论证跳步，补齐后可以投）。
- 按维度打分（问题意识与创新、论证、材料与文献、写作与规范，各 1–5 分），每个分数一句理由。
- "投稿前必须解决的几件事"：不超过 6 件，每件一句话。

## 输出格式：一份 JSON 数据

页面的样子是固定的：有一份现成的模板（`templates/dashboard.html`）负责排版和交互。你不用写 HTML、CSS、JS，只输出数据。改前 / 改后里哪些词变了，模板会自己对比并高亮。

输出一个 JSON 对象，四个键：

```json
{
  "summary": { ... },
  "issues":  [ ... ],
  "claims":  [],
  "typos":   [ ... ]
}
```

`claims` 固定是空数组：人文社科论文不做声明—证据对照表。

### summary：总判断

- `field`：固定写 `"humanities"`。页面靠它切换成人文社科的样子。
- `title`：论文题目；`venue`：目标期刊；`date`：审稿日期（YYYY-MM-DD）。
- `verdict`：一句话总判断。
- `scores`：数组，每项 `{dim, score, reason}`。四个维度：问题意识与创新、论证、材料与文献、写作与规范；score 是 1–5 的数字，可以有 .5；reason 一句话。
- `must_fix`：字符串数组，"投稿前必须解决的几件事"，不超过 6 件。每件后面写相关卡片编号，比如"界定'乡绅'的概念并全文统一（R02、R07）"。
- `passes`：数组，正好六项，每项 `{name, result}`，就是六遍检查记录。没发现问题的写"已查，未发现"。第 5 遍的 result 里写每一节各几处，0 处的也写。

### issues：修改卡片

一条意见一张卡片。字段：

- `id`：编号，R01、R02……
- `group`：类别，从这十一个里选：问题意识与创新、学术史与文献综述、核心论点、论证逻辑、概念与理论、材料与引文、研究方法、结构安排、语言表达、注释与格式、口味项。
- `priority`：P0 / P1 / P2；`effort`：小 / 中 / 大。
- `title`：用一句话说清问题本身（比如"第二章只用了地方志，没有用档案"），不要只写类别名。
- `attack`："审稿人会怎么说"，用匿名评审的口吻写一两句。
- `location`："原文位置"，写章节和段落。同一问题的其他出处也列在这里，只列位置，不再贴原文。
- `page`：quote 所在的 PDF 页码。
- `quote`：逐字引用最关键的那一句，最多两句。
- `why`："为什么是问题"，两三句。
- `approach`："修改思路"。先用两三句说清楚怎么改：方向是什么（收窄论点、补材料、补一段学术史、调整结构、界定概念），要动哪几处，为什么选这个方向；有别的可行方案的，写出来并说各自代价。
- `fixes`："最小修改"，数组，每项 `{where, before, after}`。before 和 after 都是纯文本，不要加任何标记。要补写一整段的，after 写提纲和开头一两句。
- `needs_author`："需要作者补充"。只写作者必须自己去查、去补的东西（史料、档案、文献、访谈、页码、版本），没有就是空字符串。

### typos：文字小错（第 5 遍的结果）

按出现顺序排。字段 `id`（T01、T02……）、`location`、`page`、`quote`（原文，包住错处的最短片段）、`fix`（改成什么，和 quote 对应的完整片段）、`type`（错别字 / 语法 / 标点 / 数字用法 / 外文 / 注释格式 / 其他）。

### 几条共同的要求

- `page` 是 quote 所在的 PDF 页码（从 1 数起，按 PDF 文件的页序，不是论文页脚印的页码；没有 PDF 时填 0）。
- `quote` 必须是原文里逐字能搜到的原句，不要改写、不要合并两处原文：作者要靠它在论文里找到出处，自检脚本也会逐字核对。
- 所有字段都是纯文本，不要写 HTML 标签。文字里提到别的条目时直接写编号（R03、T05），页面会把它变成可以点的链接。
- 这份数据之后可能交给另一个模型做交叉审阅，所以要完整。条目很多时也要全部写完，不要写"其余略"。
- 只写对这篇论文的分析，不要把本提示词里的规则抄进输出。
- 必须是合法的 JSON：字符串里的双引号写成 \"，反斜杠写成 \\，不要有注释和多余的逗号。中文引号“”可以直接写。

最后只输出这一个 JSON（放在一个代码块里），不要在外面再写总结。

拿到 JSON 之后怎么变成页面：
- 能运行命令：存成 `review.json`，运行 `python3 scripts/build_review.py review.json`，得到 `review.html`。
- 不能运行命令（比如网页聊天）：用浏览器打开 `templates/dashboard.html`，把 JSON 贴进去，点"生成清单"，再点页面底部的"保存成一个 HTML 文件"。
